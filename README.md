# Twitch Watcher 2.1

Telegram-бот для мониторинга активных Twitch-чатов из CSV-каталога, с историей SQLite и отдельной HTTPS-панелью. До 100 чатов одновременно по приоритету CSV. Пропущенные во время отключения сообщения Twitch не восстанавливает.

## Локальный запуск

Нужен Python 3.12 (проверенная версия). Выполняй команды из корня проекта.

1. Создай окружение: `python -m venv .venv`.
2. Активируй: Linux/macOS — `source .venv/bin/activate`, Windows PowerShell — `.venv\Scripts\Activate.ps1`.
3. Установи зависимости: `python -m pip install -r requirements.lock`.
4. Скопируй `.env.example` в `.env`. Заполни Telegram-токен, ID владельца, Twitch Client ID и Client Secret.
5. В Twitch Developer Console укажи redirect URL `http://localhost:3000`.
6. На компьютере с браузером выполни `python oauth_login.py`, открой выведенную ссылку и авторизуй аккаунт чтения чатов.
7. Выполни `python -m app.import_channels channels.csv`.
8. Запусти `python -m app.main` и отправь боту `/start`.

CSV содержит `login` и необязательный `rank`. Меньший rank означает больший приоритет. Замена каталога: `python -m app.import_channels channels.csv --replace`. История и ручные настройки сохраняются.

## Docker Compose

Сначала выполни локальные шаги 1–6 для получения токенов. Затем:

```sh
docker compose build
docker compose run --rm -v ./channels.csv:/tmp/channels.csv:ro twitch-watcher python -m app.import_channels /tmp/channels.csv
docker compose up -d
docker compose logs -f
```

В PowerShell для CSV используй `-v "${PWD}/channels.csv:/tmp/channels.csv:ro"`.

Compose сохраняет базу и токены в `./data`, явно задавая контейнерные пути `/app/data`. Веб-панель запускается отдельно на Linux с systemd и в Compose не включена.

## Токены

Обновлённые токены атомарно сохраняются в `data/twitch-tokens.json` (права 0600 на POSIX). При старте этот файл имеет приоритет над исходными токенами `.env`. По умолчанию он находится рядом с SQLite; путь переопределяется через `TWITCH_TOKEN_PATH`. Пересоздание контейнера сохраняет токены в подключённом каталоге данных.

Перед повторной авторизацией останови бота. `python oauth_login.py` обновляет `.env` и хранилище токенов. При авторизации на другом компьютере перенеси оба файла в соответствующие каталоги сервера. Не запускай два экземпляра бота с одним файлом токенов.

Не публикуй `.env`, `.env.dashboard` и `data`. Они исключены из Docker-контекста и Git. Для резервного копирования останови бот и сохрани весь `data`; для живой SQLite используй backup API.

## HTTPS-панель

Панели нужны Linux, systemd и TLS-сертификат.

1. Скопируй `.env.dashboard.example` в `.env.dashboard`.
2. Укажи домен/IP в `DASHBOARD_IP`, имя службы бота и пути сертификатов при необходимости.
3. Сгенерируй два независимых секрета командой из примера и заполни оба поля авторизации.
4. Передай абсолютный путь `.env.dashboard` через `EnvironmentFile=` своей systemd-службы. Сервер не загружает этот файл автоматически.
5. Команда запуска: `/абсолютный/путь/.venv/bin/python /абсолютный/путь/dashboard/server.py`.

Процессу нужны права на порты 80/443, чтение TLS-ключа, запись в базу и управление указанной службой бота. Настрой права под свою систему. Открывай панель по `https://DASHBOARD_IP`.

По умолчанию база, `.env` бота и файл пароля панели расположены относительно проекта. Для раздельной установки используй `DASHBOARD_DB_PATH`, `DASHBOARD_BOT_ENV`, `DASHBOARD_BOT_ROOT`, `DASHBOARD_AUTH_FILE`. При обновлении существующей панели явно сохрани прежние пути, особенно путь файла пароля.

## Обновление 2.0

Останови бот и панель; сохрани резервную копию проекта и данных. Обнови `app/`, `dashboard/`, OAuth-помощник и зависимости. Сохрани рабочие `.env`, базу, TLS-настройки и файл пароля панели. Проверь пути панели и запусти службы. Повторно импортировать CSV не нужно: схема остаётся версии 2.

Это сборка для ручной установки. Старые установщики со старыми хешами не предназначены для версии 2.1. Их копии сохранены только в `tests/legacy_ops` для регрессионных тестов; не запускай их для развёртывания.

При откате останови процессы, верни прежний код и зависимости. Историю и очередь не заменяй устаревшей копией базы. Версия 2.0 не читает новое хранилище токенов: перенеси актуальную пару из него в `.env` перед запуском старого кода.

## Проверки

```sh
python -m unittest discover -s tests -v
node --check dashboard/app.js
```

`requirements.lock` фиксирует прямые и транзитивные зависимости; используй его для установки. `requirements.txt` задаёт допустимые диапазоны для осознанного обновления. После обновления зависимостей запусти тесты и пересоздай lock в чистом окружении. Lock фиксирует версии, но не содержит проверочных хешей пакетов.

В `README-2.0.md` описаны фильтры и диагностика. Для установки следуй этому README. Старые RC-архивы, серверные логи и отчёты в поставку не включены.
