# Twitch Watcher 2.0

Личный Telegram-бот и HTTPS-панель для поиска в активных Twitch-чатах из собственного каталога. До 100 одновременно, по возрастанию приоритета, без глобального подбора и без ротации.

## Что нового

- Штатный EventSub `reconnect_url`: новое соединение получает welcome до закрытия старого; старый читатель продолжает передавать буферизованные события. Существующие подписки не пересоздаются. Невалидный адрес отклоняется.
- Состояние эфира и уведомление сохраняются одной транзакцией. При ошибке записи изменение будет обнаружено снова. Проверка ручных эфиров работает независимо от сканирования каталога.
- Живая диагностика: heartbeat, доступность Telegram API, WebSocket-пакеты, подтверждённые через Twitch API подписки, очередь и безопасные коды ошибок. Старый снимок или работающий процесс сами по себе не означают исправный мониторинг.
- В панели «База поиска»: поиск/страницы, добавление логинов, включение/выключение чтения, приоритеты, проверка и импорт CSV. Отключение поиска не выключает отдельно выбранные уведомления об эфирах.
- CSV: до 2 МБ / 20000 строк, колонка `login`, необязательная `rank`. Добавление обновляет приоритеты; полная замена требует подтверждения. Отключённые каналы, остающиеся в файле, сохраняют свой статус. Пустой/невалидный файл не заменяет базу.
- «Фразы»: исключения и интервал одинаковых уведомлений. То же доступно в Telegram через «🛡 Фильтры».

## Повторы и исключения

По умолчанию одинаковое уведомление ограничивается 60 секундами. Ключ повтора: канал + автор + текст без учёта регистра/повторяющихся пробелов + правило. Разные авторы, каналы и причины не подавляют друг друга. Настройка 0 отключает интервал. Все уникальные совпадения сохраняются в истории даже при подавлении уведомления; повтор одного Twitch message_id по одному правилу по-прежнему не создаёт дубликат истории.

Фразы-исключения ищутся с границами слов, без учёта регистра. Они полностью исключают сообщение из поиска по словам и авторам. Уведомления об активности эфиров не фильтруются.

## Работа с базой

Схема только расширяется, `PRAGMA user_version=2`. Добавлены `channel_catalog.enabled`, исключения, настройки повторов, fingerprints и runtime_status. Старые история, очередь, авторы, фразы, ручные каналы и приоритеты не удаляются. При обновлении **не нужно заново импортировать исходный CSV**.

Свежая установка: установи зависимости `requirements.txt`, настрой `.env`, выполни Twitch OAuth, затем:

```text
python -m app.import_channels channels.csv
python -m app.main
```

Повторная замена из командной строки: `python -m app.import_channels channels.csv --replace`.

## Диагностика

Бот сохраняет несекретный снимок примерно раз в 5 секунд; панель обновляет его раз в 15 секунд. Heartbeat старше 20 секунд или от другого PID считается устаревшим. Telegram проверяется отдельным `getMe` раз в 30 секунд. Пустой список активных каналов — ожидание, а не ошибка соединения. Первое подключение 100 чатов может занять до двух минут из-за Twitch join rate limits.

Фактический лимит Twitch не снимается ни большой SQLite-базой, ни несколькими сокетами одного аккаунта. Сообщения, пропущенные при отсутствии сети, Twitch не воспроизводит. При неоднозначном сетевом обрыве Telegram после отправки возможна повторная доставка: exactly-once между двумя внешними сервисами не обещается.

## Проверки и развёртывание

```text
python -B -m unittest discover -s tests -v
node --check dashboard/app.js
```

Версия проверяется отдельно от рабочего процесса. Установщик `ops/deploy_v2.py` сверяет исходные хеши, запускает тесты, проверяет миграцию на серверной копии SQLite, сохраняет резервные копии файлов/базы, затем кратко останавливает обе службы для установки. При ошибке возвращает только собственные изменения файлов; не заменяет живую историю и очередь старым снимком. Добавочная схема сохраняется при откате; старый бот не использует новые настройки 2.0.

Ключи, рабочие `.env`, TLS-сертификаты и пароли панели не включаются в ZIP и не заменяются при установке. `ops/ui_fixture.py` — исключительно локальная тестовая панель на временной базе, не входит в серверную сборку и не должна запускаться как реальная панель.

Известная отдельная задача старого Docker-режима: обновлённые OAuth-токены нужно сохранять в постоянном защищённом хранилище; текущий сервер работает через systemd с доступным `.env`.
